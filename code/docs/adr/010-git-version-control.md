# ADR-010：使用 Git 进行版本管理

- 日期：2026-09-07
- 状态：已接受

## 上下文

项目需要支持多人和多 Agent 持续开发，并让接手者能够可靠识别基线、在途变更、验证结果与历史决策。仅依赖动态交接文档无法提供文件级差异和可追溯版本历史。

## 决策

1. 使用项目根目录的 Git 仓库作为唯一版本历史事实来源。
2. `main` 作为集成基线分支，按任务需要使用带类型前缀的开发分支。
3. 提交按逻辑变更拆分，并采用 `<type>(<scope>): <summary>` 格式。
4. `AGENTS.md` 规定 Git 操作、安全边界和交接要求；`DEVELOPMENT_STATUS.md` 记录当前分支、未提交状态和任务进度。
5. Agent 负责日常版本管理，可自主创建开发分支、暂存并提交当前任务产生的已验证变更，无需逐次请求确认。
6. 推送、发布标签、受保护分支合并和制品发布仍须用户明确要求或既定交付流程授权。

## 后果

- 交接时必须同时提供 Git 状态与动态进度，避免把未提交修改误认为稳定基线。
- 代码评审、回退和发布均以 Git 提交为单位。
- 禁止嵌套 Git 仓库、强制推送和破坏性历史重写。
- Agent 应在任务完成或形成可独立验证的安全检查点时及时提交，并在交接中报告分支、HEAD 与工作树状态。
