# ADR-022：Web 首次注册与产品设置边界

- 日期：2026-09-10
- 状态：已接受
- 取代：ADR-017 的 Secret 引导条款；其会话、CSRF、锁定和密码存储条款继续有效
- 影响模块：M01、M02、M04、M10、部署配置

## 上下文

用环境变量和只读密码文件预置普通用户身份，会把产品注册混入部署运维，并使镜像首次使用需要额外手工 Secret。模型端点和重试参数也属于管理员应能在产品中调整的运行策略，而数据库、内部服务地址、Cookie 策略和凭据仍属于部署信任边界。

## 决策

1. 空数据库启动后开放一次性 `POST /api/auth/register`。账号写入与首个会话创建处于同一 PostgreSQL 事务；账号主键唯一约束裁决并发请求，胜者成功，其余请求返回冲突。账号存在后注册永久关闭。
2. 注册状态可匿名读取，仅返回是否开放，不泄露账号。就绪检查不再以账号存在为条件，使全新安装能够先打开 Web UI。
3. 复核模型端点、模型名、API Key、超时、重试和节流参数存储在 PostgreSQL，由认证且通过 CSRF 校验的管理员修改。Worker 启动时读取，变更在 Worker 下次启动生效。API Key 按用户明确选择以明文落库，但读取响应永不回显，仅返回是否已配置；空白写入保留旧值，清除必须显式选择。
4. 浏览器到服务端的机密传输依赖 HTTPS/TLS；跨主机部署必须配置 TLS 终止。本机 `localhost` 的纯 HTTP 仅用于本机访问。数据库管理员和备份读取者能够看到 API Key，这是明文落库方案的已接受风险。数据库连接、Redis、工件路径、资源/上传安全上限、会话与 Cookie 策略、代理地址和内部 Runner 地址仍是部署级配置，不进入前端。
5. 删除 `PERSONAL_USERNAME`、`PERSONAL_PASSWORD_FILE`、`PERSONAL_PASSWORD_FILE_HOST` 及模型非秘密参数的环境变量语义，不保留静默兼容路径。

## 后果

- 新安装只需启动 Compose、打开 Web、创建管理员并按需填写模型设置。
- 旧数据库中的账号与会话无需迁移，仍可直接登录；旧的 `must_change_password` 账号仍可完成一次改密。
- 从旧环境升级时，部署方须先记录模型参数（含 API Key），迁移后通过 HTTPS 在设置页重新填写；密码文件和旧模型变量应删除。
