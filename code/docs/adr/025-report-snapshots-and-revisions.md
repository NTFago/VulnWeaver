# ADR-025：报告事实快照与不可变版本

- 日期：2026-09-11
- 状态：提议，待项目负责人评审；没有实施公共协议、迁移或状态语义变更。
- 关联：[报告模块设计](../reporting-module-design.md)、ADR-012、ADR-016、ADR-020、ADR-021。
- 影响模块：M01、M02、M03、M04、M07、M16。

## 问题

现有报告按 task_id + format 标识 Job，每种格式执行时重新读取数据库。人工复核或证据变化后，不同时间生成的 Markdown/PDF/SARIF 可能表达不同结论，同格式又无法区分历史报告与新结论。ArtifactVersion 不可变，不能通过覆盖同一个版本解决。报告还可能早于 Task 最终结算生成，直接读取 Task.result 会得到空值。

## 建议决策

1. 将任务范围的一致事实读数冻结为版本化 ReportSnapshot 派生工件，包含来源记录副本、输入版本、证据关系、解释出处与截取时间。
2. 快照读取使用短的显式只读 REPEATABLE READ 事务；CAS 读取与渲染在事务外。保持 PostgreSQL/CAS 为事实来源，不用 Redis 保存最终快照。
3. 格式 Job 绑定 snapshot_id 和 template_version，通过既有 Job/Outbox 事务投递。重复生成和重试使用同一快照，新复核或模板变化生成新版本，旧产物不覆盖。
4. 历史 task+format Job 和工件保持可读；新增报告版本元数据、唯一约束、API/Job 参数和迁移须共同设计，不能只改某个渲染器。
5. 报告记录截取时 Task 状态；分析摘要复用领域/编排层只读投影，不改变 Task 的持久化状态机，也不绕过自动 Markdown 结算门禁。
6. 中文解释与来源引用作为版本化结构化派生产物接入快照。模型不得修改 Finding 的等级、状态和证据；渲染器不调用模型。

## 不变的边界

默认自动 Markdown、PDF/SARIF 按需；不新增报告服务或队列框架；原始工件不可变；确认规则仍由 FindingPolicy 拥有；报告不执行样本。此提议是对报告跨组件身份与事实绑定协议的补充，不能自动解释为允许更改确认或任务结算语义。

## 代价与替代方案

快照增加少量存储和元数据维护，但可以复放同一事实版本并阻止格式漂移。仅使用实时数据库重渲染实现简单，却无法固定历史结论；覆盖旧报告违反工件不可变；只保存行 ID 不能冻结会变化的 Finding 状态。因此建议接受有界事实快照，并复用现有 CAS 注册与权限模型。

多样本的完整来源放快照清单，ArtifactVersion 现有单 parent 作为主谱系边；新增数据库多父关系不属于本提议。

## 接受前必须补齐

- 报告版本元数据的表结构、唯一约束、快照绑定与 Outbox 事务边界。
- ReportSnapshot/解释产物的 JSON Schema、兼容策略和全部消费者。
- 旧固定 Job ID 与新版本协议兼容、自动报告不重复调度的集成用例。
- 并发复核、失败重试、跨项目引用、多格式一致性与资源预算用例。
