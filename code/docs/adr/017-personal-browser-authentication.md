# ADR-017：个人部署的浏览器认证与会话边界

- 日期：2026-09-08
- 状态：已接受
- 影响模块：M01、M02、M04、部署配置

## 上下文

首版是单人本地部署，不需要成员、角色或 RBAC，但浏览器控制面仍会执行上传样本、创建任务和开启验证等敏感操作。把明文口令长期放在环境变量、把令牌交给前端持久化，或让每个 API 实例维护进程内会话，都会增加泄露、重启失效或多实例不一致风险。Argon2 校验本身还可能被并发登录请求放大为 CPU 与内存拒绝服务。

## 决策

1. 首版只保留一个 `personal` 账号。首次启动从只读 Secret 文件引导，PostgreSQL 只保存 Argon2id 哈希；账号存在后，重启不再读取或重新哈希引导 Secret。
2. 登录签发高熵不透明会话令牌和独立 CSRF 令牌，数据库仅保存二者的 SHA-256 摘要。会话 Cookie 使用 `HttpOnly`、`SameSite=Strict`，生产默认要求 `Secure`；CSRF 令牌通过响应体和可读的同站 Cookie 交给浏览器，并须在写请求的 `X-CSRF-Token` 中回传。
3. 登录失败计数、锁定截止时间、密码版本和会话都以 PostgreSQL 为事实来源。未知账号也执行一次虚假 Argon2 校验，密码哈希/校验使用有界并发，活动会话数量有上限，过期会话在启动及登录时清理。
4. 改密必须携带幂等键，在数据库事务中串行化；成功后保留当前会话、提升密码版本并撤销其他会话。重复请求返回相同成功语义，不会因旧口令已失效而误报失败。
5. 登出删除服务端会话和浏览器 Cookie。对已经失效的会话保持幂等成功；有效会话仍要求 CSRF 校验。
6. 所有认证 DTO 都进入 v1 公共 Schema 和 OpenAPI；框架错误、认证错误与请求限额错误统一返回版本化结构。

## 后果

- 单人部署不引入团队权限模型，但浏览器写操作具有明确的认证、CSRF、锁定和会话撤销边界。
- 多 API 实例共享一致会话状态，进程重启不会迫使用户重新引导账号。
- 部署方必须保护首次引导 Secret，并在首次登录后改密；TLS 终止时保持 `SECURE_COOKIE=true`。
- 若未来增加多用户或外部身份提供方，需要新 ADR 和独立迁移，不能复用单账号表硬扩展 RBAC。
