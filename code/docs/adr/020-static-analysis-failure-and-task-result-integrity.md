# ADR-020：静态分析失败与任务结果完整性

- 日期：2026-09-09
- 状态：已接受
- 影响模块：M01、M03、M07、M09、M15

## 上下文

静态分析 Worker 以只读根文件系统和只读源码树运行。Semgrep 即使关闭遥测和版本检查，仍会写入用户设置和日志目录；若沿用默认用户目录会在工具启动前失败。

此前静态执行器无论工具结果是成功、不可用还是失败，都会把空诊断列表写入派生结果并把 Job 结算为 `succeeded`。Task 聚合只看到成功 Job 和零个 Finding，错误地显示为 `completed/no_findings`。同时，终态聚合通过固定阶段列表补齐了没有对应 Job 的 `reviewing` 和 `reporting` 事件。

## 决策

1. Semgrep 子进程只使用由执行器创建的临时 `HOME` 与 `SEMGREP_SETTINGS_FILE`。临时目录位于 Worker 已有的可写 tmpfs，命令仍固定、无 Shell，控制面凭据仍不传入子进程。
2. 每次静态工具运行都会先登记不可变 `StaticAnalysisResult`。若工具失败、不可用，或以零退出码返回了不符合声明格式的结果，结果工件保留工具状态和原因，但 Job 以结构化 `failed` 结算，并引用该产物。
3. 只有工具成功且输出成功解析时才投影 Finding/Evidence 并结算 Job 成功。`no_findings` 因而仅表示已执行的工具产生了合法的零诊断，不再表示“工具没有给出可解析结果”。
4. Task 的终态路径根据实际存在的 Job 类型生成阶段事件。合法状态迁移允许在实际最后阶段后直接进入 `completed`；不会为了满足旧的线性路径虚构复核、验证、利用或报告阶段。
5. 前端将 Task 结果转换为面向用户的中文含义，并显示 Job 的结构化失败代码、工具名、原因与退出码（如有）。本次不实现报告生成或报告下载。

## 后果

- 导入成功、静态扫描失败的任务会显示为 `completed/partial`，而不是 `completed/no_findings`；所有执行单元都失败时仍为 `failed`。
- 静态工具故障保留可审计的派生结果及 Job failure，而不会产生候选 Finding。
- 分析 Worker 保持非 root、只读根、只读样本和禁外网边界；增加的可写空间仅是单个工具进程生命周期内的 tmpfs 临时目录。
- 历史任务不会被自动改写。重新投递或新建任务后使用新的、准确的结算语义。
